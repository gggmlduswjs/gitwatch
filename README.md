# gitwatch

여러 git worktree 상태를 한 화면에 보는 **읽기 전용** 관제판 (Windows). 의존성 0, Node 20+.
본보기: 김민태 GitWatcher(macOS, 비공개 — 터미널 부품 수정만 공개 `ibare/SwiftTerm@gitwatcher`).

```
node server.mjs C:\path\to\repo [다른 레포 ...]
# → http://127.0.0.1:3810   (GITWATCH_PORT · GITWATCH_BASE=origin/main 로 바꿈)
```

- 칸: worktree · 브랜치 · 변경(커밋 안 된 파일 수) · 앞섬/뒤짐(기준 브랜치 대비) · 마지막 커밋
- 조회 실패는 0 이 아니라 「조회 실패」로 보인다. fetch 하지 않는다(로컬 `origin/main` 기준).
- 기본은 「전체 공간」이며 모든 워크트리를 펼친 리스트로 표시한다. 30초마다 갱신.

## 워크트리 리스트 표시

- 프로젝트별로 모든 워크트리를 한 표에 표시한다. 영역 카드나 미등록 목록 접기 없이 작업공간을 한 줄씩 볼 수 있다.
- 정확한 슬롯 전체 경로가 일치해야 영역으로 분류한다. 제목은 `웹`, `프론트엔드`, `백엔드`, `AI 워크플로우`, `모바일`처럼 짧게 표시한다.
- 기준 작업공간은 관리·통합용으로 표시한다. 임시·외부 공간도 같은 리스트에 표시하며 변경 있는 행은 강조한다.
- 브랜치는 작업 열에서 한 번만 표시한다. 긴 브랜치는 줄임표와 툴팁, 전체 경로·해시·커밋 메시지는 상세에 둔다. 마지막 커밋을 현재 작업명으로 추정하지 않는다.
- 검색과 최근 변경 필터로 목록을 좁힐 수 있다. 갱신 시 사용자가 펼친 상세 상태를 유지한다. 최근 변경 필터는 변경 파일·앞섬·7일 이내 커밋·조회 오류 기준이며 실행 중인 세션 수를 뜻하지 않는다.
- 공유 `harness/workflow.json`의 경로·브랜치가 맞는 작업을 사용하고, 없으면 `.slot-lock`·phase 명세를 참고한다. 잠금 기록은 프로세스 생존 증명이 아니다.
- Gitwatch는 읽기 전용이다. 생성·진입 검사는 하네스 launcher와 로컬 Claude/Codex 훅이 담당한다. 훅 설치·신뢰 여부를 Gitwatch가 검증하지 않으므로 `차단됨`으로 표시하지 않는다.

검증: `node --test metadata.test.mjs`.
